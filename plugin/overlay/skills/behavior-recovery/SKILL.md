# Behavior Recovery — Goal and Evidence First

Trigger on owner correction, repeated failure, context break, unsupported claim, wrong routing, hallucination risk or premature handoff.

1. Load `skills/goal-anchored-context-integrity/SKILL.md` and `skills/owner-expectation-closure-gate/SKILL.md`. Reconstruct `original owner goal -> MUST criterion -> expected behavior -> required workflow/gate -> actual action/tool call -> observed result -> evidence`. Do not reconstruct from the latest assistant summary alone.
2. Recover the exact project/ticket, original request, scope/non-goals, acceptance ledger, source authority, repo/ref/SHA, prior attempts and current recovery cursor. Re-read live canonical source when checkpoint and source disagree.
3. Inspect project `AGENTS.md`, contracts and deterministic gate scripts before retry. Invoke the project-owned gate exactly as required; never substitute a generic validator or claim an uninvoked gate passed.
4. For a named GitHub PR/repository, inspect live PR/Issue, exact head/base SHA and automatic CI run before any local environment probe. The repository CI preflight is authoritative for that revision; a ChatGPT-local preflight must never block GitHub connector access.
5. **Mandatory Git Tree-first Actions recovery and identifier integrity:** lock the exact source commit/root tree, workflow/request blobs and source-bound receipt first. A URL `/actions/runs/{N}` contains `run_id=N`, never `runner_id`; `/job/{N}` contains a job ID. Check-run IDs are separately typed even if numerically equal to a job ID. Verify the exact run ID, workflow, attempt and head SHA, then resolve the exact-SHA check-run and inspect its annotation before fetching job/runner/step metadata. If the annotation explicitly names failed payment or a spending-limit/Actions-billing restriction, classify `QUOTA_EXHAUSTED` and stop quota diagnosis. If the annotation endpoint is blocked, preserve `annotations_url` and count, record `API_METHOD_BLOCKED`, and try one materially different authorized route; do not claim the annotation is absent or read. Only when the annotation is non-decisive or actual execution is independently required, continue `Git Tree → blob/receipt → runner_id → job_id → run_id + attempt → head_sha → actual execution` using raw attempt-scoped job JSON. Preserve PRESENT/NULL/MISSING and keep every identifier type distinct. `BlobNotFound` is only a log-retrieval failure. Owner-supplied exact annotation text may be used as REPORTED evidence, not connector-retrieved evidence.
6. A connector wrapper failure is a failure of that access path, not the end of investigation. Inspect filters/pagination and try another authorized provider route, with bounded retries.
7. **Goal revalidation after failure:** after the first failed attempt, re-read the original expectation and every MUST before retry. Before a second attempt or after a second failure of the same method, revalidate the full goal, source lock, assumptions and evidence; change the method or evidence route. Never repeat the same failed action without new decision-relevant evidence.
8. **Bound hypotheses:** keep one active falsifiable hypothesis per failure branch, with evidence, expected signal, falsifier and discriminating test. A hypothesis is not a fact and cannot fill missing context. If two iterations add no new evidence, close that diagnostic branch as UNKNOWN where appropriate and continue independent goal criteria.
9. **Do not loop on an evidence-missing run.** If the run is terminal and has no executed steps/log/provider cause after bounded alternate-route checks, classify `EXECUTION_EVIDENCE_MISSING` and causal status `UNKNOWN`, record exact run/SHA and evidence attempts, then close that run's diagnostic branch. Do not repeatedly re-fetch or re-explain the same missing evidence unless new provider evidence appears or the owner explicitly asks.
10. **Continue the whole failure sweep.** Inspect every other relevant failed job, run, build, check and downstream workflow for the target revision. Diagnose failures with actual steps/logs/annotations; repair the responsible layer, retest, and keep independent acceptance work moving. One opaque run is not a blanket blocker.
11. Missing local skill/catalog files are context gaps. Recover them from canonical plugin/project source where possible; never falsely claim they were loaded. If the original goal or evidence remains unavailable, mark `UNKNOWN`; do not invent a substitute.
12. Derive positive, negative, boundary and counterexample tests from owner requirements and authoritative behavior. Read back exact changed source/revision and continue through consumer E2E, adversarial review, repair/retest and acceptance.
13. Finish feasible AI-owned production and QA before owner handoff. Ask for owner-only testing only when real installed device/account/access is genuinely required.

## No false completion
Never claim CI preflight, host enforcement, runtime acceptance or overall completion without direct evidence. Report the complete original goal and acceptance ledger, not merely the latest repaired symptom. A closed diagnostic branch is not a passed gate; it only prevents repeating an exhausted evidence search while the remaining goal proceeds. Do not issue a partial report while AI-owned work remains runnable.

## ChatGPT connector routing correction

When the active host is ChatGPT, call `mcp__GitHub__fetch` via `functions.exec` for the exact run and attempt-scoped jobs REST endpoints and inspect raw JSON before classifying a failure. `fetch_workflow_run_jobs` is a lossy convenience wrapper, not the source of truth for runner fields. Preserve missing/null/zero distinctly. If the REST payload itself contains `runner_id: 0`, do not infer the cause from that field alone. If a REST endpoint is rejected by the connector allowlist, record `API_METHOD_BLOCKED` and use another evidence route.
