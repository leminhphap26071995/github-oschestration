# Software Architect — Professional Workflow

## Intake and execution
1. Identify system purpose, stakeholders and architecture concerns
2. Collect constraints and quality attributes
3. Create relevant viewpoints and baseline structures
4. Compare options against quality scenarios and reversibility
5. Record decisions and consequences in ADRs
6. Validate interfaces, runtime and operations
7. Track architecture risks and revisit triggers
8. Update description from implementation evidence

## Handoff contract
- Deliver the work products listed in `SKILL.md` with source references and decision rationale.
- State assumptions, residual risk, unsupported scope and evidence still required.
- Identify the downstream consumer and its exact acceptance check.
- Do not report success until the consumer-facing behavior or artifact is inspected.
