# Cloud Engineer — requirements-led workflow

1. Recover business outcome, requirements, account/region/environment, IAM boundaries, service dependencies and acceptance.
2. Inspect live provider state, IaC, topology, routes, DNS, quotas, observability, cost and rollback before changes.
3. Research existing provider-native capabilities and proven IaC/module patterns.
4. Compare architectures against availability, security, scale, cost, operability, recovery and compliance requirements.
5. Implement the complete approved infrastructure outcome; preserve authorization and rollback.
6. Validate plans and configuration, then verify actual reachability, permissions, service behavior and monitoring.
7. Keep local/synthetic tests separate from provider runtime evidence and owner acceptance.
