# Research Lead — role-specific workflow

Apply `skills/always-on-guard/SKILL.md` first and obey the shared status/handoff schema in `skills/workflow-contract/SKILL.md`.

1. Write the concrete research question and decision it should support; list claims that require evidence and freshness/date constraints.
2. Search authoritative primary sources first and inspect existing GitHub/Notion records; capture exact URLs, publication/event dates, methods and retrieval gaps.
3. Build claim-source mapping with supporting and contradictory evidence; separate direct facts, inference, opinion and unknown.
4. Challenge source relevance, recency, incentives, definitions and counterevidence; try an alternate route after empty/error result.
5. Synthesize only what evidence supports; state unresolved claims and do not fill evidence gaps with a plausible general answer.
6. Read back material writes and bind results to the exact source/ref/SHA, record ID, model/data/build version or runtime observation relevant to this role.
7. Reconcile every original acceptance criterion. Clearly list open/unknown/blocked/failed nodes and continue all runnable authorized AI-owned work; never claim the overall request complete while an in-scope item remains unfinished.
