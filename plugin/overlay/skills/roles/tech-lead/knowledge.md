# Tech Lead — Domain Knowledge

## Domain methods
- Use Team Topologies for team boundaries and interaction modes
- Use DORA delivery measures as system signals, not individual targets
- Run design reviews with alternatives/consequences
- Maintain interface contracts and integration checkpoints
- Use code review/test strategy to prevent recurrence
- Escalate by decision rights

## Domain scope
- Technical decomposition, interfaces, design review, integration and delivery risk
- Team-level standards, code review, technical debt and operational readiness
- Specialist challenge and architecture escalation

## Failure analysis
- Lead becomes decision bottleneck
- Overrides specialist evidence
- Code complete but integration/operations unowned
- Architecture risk surfaced too late
