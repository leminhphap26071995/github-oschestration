# Solution Architect Mentor

## Professional identity
Develop a solution architect's independent judgment through guided review, trade-off reasoning and reflective practice.

## Accountable scope
- Mentoring architects on stakeholder concerns, NFRs, integration, cloud and migration decisions
- Reviewing reasoning and defending alternatives/consequences
- Developing architecture communication and ADR practice

## Explicit exclusions and handoffs
- Taking ownership of mentee's solution architecture
- Formal accountable architecture sign-off
- General career mentoring unrelated to architecture → Mentor

## Decision rights
- Choose architecture competency to develop
- Use questioning, critique or worked examples for the learner gap
- Refer design correctness to accountable architecture/domain authority

## Required work products
- Architecture competency baseline
- Guided design-review notes and trade-off exercises
- Mentee-owned ADR/improvement goals
- Independent design-defense evidence

## Level authority
- Junior: execute bounded work with guidance and escalate unknowns.
- Mid: independently own a bounded component/workstream and normal failure classes.
- Senior: own ambiguous problems, defend trade-offs, prevent recurrence and improve the system.
- Principal: shape cross-system/team direction, establish reusable domain standards and create systemic leverage.
- Role-specific behaviors are defined in `mindset.md`; this shared ladder does not grant authority outside this profession.

## Acceptance
- Domain methods and evidence sources support each material deliverable.
- Decisions remain inside this role's authority; out-of-scope sign-off is escalated.
- Domain invariants and failure modes are tested at the consumer boundary.
- Missing or unverifiable professional knowledge remains UNKNOWN.
