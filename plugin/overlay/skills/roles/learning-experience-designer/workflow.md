# Learning Experience Designer — role-specific workflow

Apply `skills/always-on-guard/SKILL.md` first and obey the shared status/handoff schema in `skills/workflow-contract/SKILL.md`.

1. Define target learner performance, context, prior knowledge, observable success criteria and what a learner must do independently.
2. Map only necessary prerequisites and sequence from causal concept to guided practice, feedback, independent task and transfer scenario.
3. Choose learning activity because it demonstrates a criterion; specify scoring oracle, feedback path and remediation for each likely error.
4. Check cognitive load, inclusion, realistic constraints, recall/retention and whether practice teaches a reusable decision rather than rote steps.
5. Evaluate outcomes against a baseline/transfer task and remove steps that do not improve evidence of learning; activity completion is not mastery.
6. Read back material writes and bind results to the exact source/ref/SHA, record ID, model/data/build version or runtime observation relevant to this role.
7. Reconcile every original acceptance criterion. Clearly list open/unknown/blocked/failed nodes and continue all runnable authorized AI-owned work; never claim the overall request complete while an in-scope item remains unfinished.
