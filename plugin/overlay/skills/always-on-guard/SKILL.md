# Always-on Guard

This is a behavioral contract, not proof of host-wide enforcement.

## Mandatory entry order
- Simple chat/content-only tasks: answer directly.
- Substantive, resumed, corrective, state-dependent or tool-backed work: execute `skills/execution-preflight/SKILL.md` before project/source investigation or consequential project-facing tools.
- Before the visible receipt, read only UPW entry skills, canonical plugin-root registries, professional-capability catalog, host execution contract and exact selected role bundles.
- For owned personal UPW plugin source, use Plugin Creator `list_owned_personal_plugins` first, capture exact plugin_id/current_release_id, then `get_plugin_files`.
- Owner corrections also load behavior-recovery and chat-mode-closed-loop.

## Context isolation
- Apply `skills/project-ticket-context-isolation/SKILL.md` for all project-specific, resumed, cross-session and context-switching work.
- Resolve by explicit project_id + ticket_id/goal_id; never select the newest checkpoint.
- Root CURRENT is an index only. Project and ticket checkpoints are separately namespaced.
- Game Mod, VS Code Extension, Career/Interview and other projects must not share role state, source locks, acceptance ledgers or Next Actions.

## Professional capability coverage
- Always derive lifecycle, deliverables, domain disciplines, specialist roles and acceptance oracles from the requested outcome before finalizing a WBS.
- Read `skills/professional-capability-discovery/SKILL.md` and `references/professional-capability-catalog.json`.
- Generic PM/BA/Tech Lead/Architect roles coordinate; they do not replace specialist production such as art, clinical, legal, financial, scientific, design, regulatory or operational work.
- If a required specialist is missing, create and load a task-scoped complete four-artifact bundle before implementation. Do not silently use a generic role as fallback.
- Every deliverable must have an owner, consumer, dependency and acceptance oracle.

## Preflight and evidence
- Read workflow-contract, role-registry, domain-routing, professional-capability catalog, host execution contract and every selected four-artifact role bundle in full.
- Preflight runs in the active host that owns the next tool invocation. ChatGPT Python/container is bounded optional compute, not the user's device or a host permission broker.
- Plugin guidance is not hard enforcement. Host enforcement requires actual broker gate and negative invocation tests.
- Preserve source/runtime/artifact/consumer/owner acceptance as separate gates. Never claim unobserved tool access, quota state, worker, review or completion.
